# Home Row Mods: переход на `tap-preferred`

**Дата:** 2026-07-04
**Файл:** `config/eyelash_corne.keymap` (hold-tap `hml`, `hmr`)
**Ветка:** `hrm-tap-preferred`

## Контекст и проблема

Пользователя раздражают **ложные моды при быстрой печати** — вылезают случайные
заглавные буквы и модифицированные символы, когда ZMK не отличает «печатаю быстро»
от «держу модификатор».

Текущая конфигурация HRM (`balanced` + позиционный cross-hand режим +
`hold-trigger-on-release` + `require-prior-idle-ms = 175`) защищает от ложных
срабатываний только пока печать **непрерывна**. Любая естественная пауза
≥175 мс (между словами, в конце предложения, во время обдумывания) снова
открывает окно, и следующий cross-hand ролл даёт ложный мод. Задержку и
same-hand связки пользователь отдельной болью не отметил — латентность модов
для него не критична.

## Решение

Перевести HRM на flavor `tap-preferred` (time-based): клавиша разрешается как
буква, если только она не удержана дольше `tapping-term-ms`. Позиционную логику
(cross-hand) убрать — с чисто временным разрешением она не нужна.

## Изменение

`QUICK_TAP_MS` (175) остаётся как есть и используется для обоих защитных порогов.

### Было

```c
ZMK_HOLD_TAP(hml,
    flavor = "balanced";
    tapping-term-ms = <200>;
    require-prior-idle-ms = <QUICK_TAP_MS>;
    hold-trigger-key-positions = <KEYS_R THUMBS>;
    hold-trigger-on-release;
    bindings = <&kp>, <&kp>;
)

ZMK_HOLD_TAP(hmr,
    flavor = "balanced";
    tapping-term-ms = <200>;
    require-prior-idle-ms = <QUICK_TAP_MS>;
    hold-trigger-key-positions = <KEYS_L THUMBS>;
    hold-trigger-on-release;
    bindings = <&kp>, <&kp>;
)
```

### Станет

```c
ZMK_HOLD_TAP(hml,
    flavor = "tap-preferred";
    tapping-term-ms = <180>;
    require-prior-idle-ms = <QUICK_TAP_MS>;
    quick-tap-ms = <QUICK_TAP_MS>;
    bindings = <&kp>, <&kp>;
)

ZMK_HOLD_TAP(hmr,
    flavor = "tap-preferred";
    tapping-term-ms = <180>;
    require-prior-idle-ms = <QUICK_TAP_MS>;
    quick-tap-ms = <QUICK_TAP_MS>;
    bindings = <&kp>, <&kp>;
)
```

### По свойствам

- `flavor` → `tap-preferred`: мод срабатывает только при удержании дольше
  `tapping-term-ms`, независимо от других клавиш.
- `tapping-term-ms` `200` → `180`: порог удержания для намеренного мода. Главный
  тюнинг-диал после прошивки.
- `require-prior-idle-ms` — оставить `175` (`QUICK_TAP_MS`): доп. защита, форсирует
  букву, если другая клавиша была отпущена менее 175 мс назад.
- `quick-tap-ms = <QUICK_TAP_MS>` — **добавить**: повторное нажатие той же клавиши
  в течение 175 мс форсируется в букву (помогает сдвоенным буквам вроде `ll`, `tt`).
- `hold-trigger-key-positions` + `hold-trigger-on-release` — **убрать**: позиционная
  cross-hand логика больше не нужна.

## Ожидаемый эффект

| | Было | Станет |
|---|---|---|
| Ложные моды при печати | возможны после паузы ≥175 мс + cross-hand ролл | фактически исчезают |
| Same-hand связки (мод + буква одной рукой) | не работали | работают снова |
| Намеренный мод | мгновенно по роллу | требует удержания ~180 мс |
| Двойные буквы | зависели только от `require-prior-idle-ms` | дополнительно защищены `quick-tap-ms` |

**Плата:** намеренный мод требует короткого удержания (~180 мс). Пользователь не
жаловался на латентность, поэтому цена считается низкой.

## Верификация

- **Компиляция:** локальной сборки нет (нужен Zephyr SDK). Проверяется через
  GitHub Actions: `eyelash_corne_left//zmk` и `eyelash_corne_right//zmk`.
- **Ощущения:** `tapping-term-ms` субъективен и реально валидируется только
  прошивкой и эксплуатацией. Стартовое значение `180` — отправная точка под
  фидбек.

## Тюнинг после прошивки

Главный диал — `tapping-term-ms`:
- ложные моды всё ещё появляются → ниже (маловероятно с `tap-preferred`);
- намеренный мод ощущается «клейким»/медленным → ниже;
- намеренный мод трудно удержать / срабатывает нестабильно → чуть выше.

`require-prior-idle-ms` и `quick-tap-ms` оставить на `175`.

## Откат

Изменение локализовано в одном файле. Откат — `git revert`.

## Вне скоупа

- `Q = LCTRL` на верхней строке слева дублирует `S = LCTRL` на home row. К ложным
  модам отношения не имеет; под `tap-preferred` тоже станет безопасным. Не трогается.
- `#define KEYS_L / KEYS_R / THUMBS` после удаления позиционного режима становятся
  неиспользуемыми. **Решение: оставить как есть** — ноль риска, ноль стоимости,
  могут пригодиться, если для отдельных клавиш позже вернём позиционный режим.
  Мёртвые препроцессорные макросы в devicetree не вызывают ошибок/предупреждений.
